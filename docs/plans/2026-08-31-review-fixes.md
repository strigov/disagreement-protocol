## Исправления

- [x] **R01 — покрытие и актуальность отчёта.** Подсчёт учитывает происхождение строк, включая объединённые пункты и структурные правки таблиц. Удалённые строки и строки с обеими пустыми редакциями не покрывают исходные правки. Отчёт пересчитывается при изменениях и перед экспортом.
- [x] **R02 — курсор в редакторе.** Ячейки сохраняют DOM-идентичность во время ввода. Проверен ввод в середине значения для input и textarea.
- [x] **R03 — перемещения Word.** `moveFrom` входит в исходную версию, `moveTo` — в принятую. Неполные пары и ошибки сопоставления сопровождаются диагностикой.
- [x] **R04 — структурные правки таблиц.** Вставки и удаления строк/ячеек проходят через разбор, БД, построение и экспорт. Неподдерживаемый `cellMerge` отклоняется явно.
- [x] **R05 — сохранение перед экспортом.** Экспорт и структурные операции ждут сохранения всех черновиков, включая активную ячейку без blur. Ошибка блокирует переход, сохраняя введённый текст для повторной попытки.
- [x] **R06 — зависимости и HTTP-загрузка.** Обновлены прямые и транзитивные зависимости и lock-файлы. Ограничения тела запроса применяются до multipart-парсера; ограничены число частей, заголовки и время чтения. Проверена очистка временных файлов при отказе.
- [x] **R07 — локальный доступ.** Backend и команды frontend dev/start привязаны к `127.0.0.1`. Добавлены проверки Host/Origin. Фактические production-сокеты обоих серверов проверены через `lsof`.
- [x] **R08 — порядок блоков.** Индексы абзацев и таблиц сохраняются через БД. Для старых записей порядок восстанавливается из исходного DOCX, когда доступны идентификаторы блоков; иначе выдаётся предупреждение.
- [x] **R09 — объединение строк.** Направление previous/next сохраняет исходный порядок текста; объединяются номера пунктов, происхождение и флаги. Явно изменённая согласованная редакция остаётся ручной.
- [x] **R10 — порядок строк.** После merge/delete и перед add индексы нормализуются; добавление в конец работает и для старых записей с пропусками.
- [x] **R11 — асинхронное состояние интерфейса.** Обновления используют актуальное состояние React; зависимые операции согласованы с сохранениями. Двойные структурные команды блокируются, а ошибка операции не размонтирует редактор.
- [x] **R12 — смена стороны и роли.** Общий сервис обновляет автоматическую согласованную редакцию в обоих маршрутах. Явные ручные значения сохраняются; изменение других колонок этому не мешает. После изменения экспортированного документа статус возвращается в built.
- [x] **R13 — нумерация.** Учитывается `lvlRestart`, включая 0 и выбор уровня перезапуска. Проверены значения по умолчанию и недопустимые значения согласно правилам OOXML.
- [x] **R14 — завершение фоновой обработки.** Ошибки инициализации хранилища, чтения, разбора и записи результата переводят документ в failed после отката. При старте прерванные uploaded/parsing получают объяснение сбоя; повторный запуск завершённой задачи не создаёт дубликаты.
- [x] **R15 — бюджеты ZIP/XML.** Общая граница обработки действует во всех точках входа: проверка каталога ZIP до выделения записей, фактического конца потока, размеров и CRC, числа XML-узлов, глубины и времени. ZIP64 не может подменить предварительно проверенный каталог. Обработка соседних runs линейная; общий дедлайн действует и после построения XML-дерева. DTD, внешние сущности, неподдерживаемые архивы и лишняя параллельная обработка ограничены.

Миграция добавляет поля без пересоздания пользовательских таблиц. Тесты используют отдельные SQLite и файловое хранилище. Пользовательские `docs/future.md` и `docs/plans/finished/2026-07-26-disprot-defect-fixes.ledger.json` не изменялись.

Регрессии сохранены в `backend/tests/integration/test_review_fixes.py`, `backend/tests/integration/test_upload_security.py` и `frontend/__tests__/ReviewRegressions.test.tsx`. Проверяются настоящая SQLite, миграция старой схемы, сохранение ручных правок, содержимое экспортированного DOCX и управляемые задержки/ошибки UI-запросов.

Отдельно пройден сценарий через реальные production-процессы Next.js → Uvicorn с временными БД и хранилищем: загрузка DOCX → анализ → стороны → построение → редактирование → merge/add/delete → смена составителя → экспорт и повторное чтение DOCX. В результате сохранены порядок строк, ручная редакция и заголовки сторон; исходный файл скачивается без изменений.

На обоих портах, напрямую и через Next.js, файл ровно 26 214 400 байт принят с 201; превышение размера файла на один байт и тела chunked-запроса возвращают 413. Посторонний Origin получает 403. Проверенный запрос с неоднозначным Content-Length/Transfer-Encoding получает 400; отвергнутые запросы не создают документы. Это отдельные регрессии HTTP-обработки, не полный pentest.

Независимый ревьюер обнаружил три обхода первоначального исправления R15: ZIP64 locator внутри комментария записи менял каталог после проверки; длинный абзац с одинаковыми runs обрабатывался квадратично; ZipExtFile обрезал распакованный поток по поддельному file_size. Все три устранены в этом же цикле, без запуска дополнительных ревьюеров. Проверены скрытый ZIP64-каталог до вызова ZipFile, поддельные размер/CRC во всех пяти точках входа, оборванный и склеенный Deflate, нормальные ZIP data descriptors, общий дедлайн в обработчиках дерева и стадиях пайплайна.

Контрольный документ с 50 000 runs и 11 000 000 символов: XML-валидация 0,137 с, обработка дерева 0,110 с, весь пайплайн 1,638 с. Ранее обработка дерева продолжалась дольше 12 секунд. Это замер на текущей машине, не норматив производительности для другого оборудования. После этих исправлений реальный HTTP-сценарий и граничные размеры повторно прошли.

## Совместимость и пределы

- Обновлены Next.js до 15.5.24, React до 19.2.8, FastAPI до 0.141.1, Starlette до 1.6.0 и python-multipart до 0.0.32. PostCSS 8.5.26 закреплён также для вложенной зависимости Next. Нужны Python 3.12 и Node.js 22.19+; фактический прогон выполнен на Python 3.12.13 и Node.js 26.5.0.
- Для воспроизводимой установки используйте `uv sync --frozen --python 3.12 --extra dev` и `npm ci`. Перед обновлением сделайте копию локальных данных; удалять базу не требуется.
- Приложение рассчитано на один локальный процесс backend. Интернет-публикация и несколько Uvicorn workers не поддерживаются этой конфигурацией.
- Покрытие означает наличие строк, происходящих из исходных пунктов. Оно не подтверждает смысловую или юридическую корректность текста после ручного редактирования.
- Для старых строк без отдельного признака ручного изменения agreed_text используется консервативный `user_edited`: такие значения не перезаписываются автоматически. Существующие протоколы с ручными правками не перестраиваются при запуске приложения.
- Вложенные таблицы и правки объединения ячеек требуют предварительной обработки. Полные лимиты ZIP/XML и загрузки описаны в README.
- Дедлайн проверяется кооперативно: он не прерывает отдельный выполняющийся вызов сторонней библиотеки и не заменяет изоляцию процесса. Ограничения размеров и сложности действуют дополнительно к нему.
- Реальный визуальный просмотр результата в Word/LibreOffice, браузерный E2E, аварийное выключение ОС и исчерпание ресурсов не выполнялись. UI проверен в jsdom; HTTP-проверки выполнены на настоящих серверах.
