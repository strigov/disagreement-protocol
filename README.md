## Зачем это нужно

Когда контрагент возвращает договор с правками в режиме рецензирования, изменения нужно перенести в протокол: указать пункт, исходную редакцию, предлагаемую и согласованную. Приложение разбирает правки в `.docx`, собирает таблицу и помогает проверить каждое разногласие перед экспортом.

Для работы готового настольного приложения не нужны Microsoft Word, Python, Node.js или интернет.

## Возможности

| | Что можно сделать |
| :--- | :--- |
| **Разобрать правки** | Извлечь вставки, удаления и перемещения текста, изменения строк и ячеек таблиц. Проверить замечания обработки и нумерацию пунктов. |
| **Указать стороны** | Проверить распознанные названия и роли, заполнить их вручную и выбрать нашу сторону. |
| **Согласовать редакции** | Работать по пунктам с подсветкой различий или в общей таблице. Редактировать текст, добавлять строки, объединять соседние и исключать лишние. |
| **Пройти проверку** | Искать пункты, фильтровать требующие внимания и отмечать проверенные. Контроль полноты помогает увидеть, какие исходные правки выпали из протокола. |
| **Оформить документ** | Задать реквизиты договора, дату, место, шапку, названия колонок, заключительные положения и подписи. |
| **Сохранить результат** | Экспортировать DOCX: A4, альбомная ориентация, таблица из четырёх колонок с повторяющимися заголовками. Продолжить работу с сохранённым договором позже. |

Интерфейс в стиле **«Бюро»**: тёплая бумага, спокойная типографика, светлая и тёмная темы. Шрифты включены в приложение и загружаются локально.

## От договора к протоколу

1. **Загрузите договор** — выберите `.docx` с правками Word Track Changes.
2. **Проверьте стороны** — уточните названия, роли и укажите нашу сторону.
3. **Пройдите разногласия** — сравните редакции, внесите изменения и отметьте проверенные пункты.
4. **Настройте оформление** — заполните реквизиты и подписи, проверьте предпросмотр.
5. **Сохраните DOCX** — выберите имя и место для итогового документа.

Правки текста сохраняются при выходе из поля или по **Ctrl / ⌘ + Enter**. **Esc** отменяет текущую правку. Личные отметки проверки сохраняются отдельно и не попадают в экспортируемый документ.

## Установка

Настольная версия собирается для трёх платформ:

| Платформа | Файл |
| :--- | :--- |
| Windows x64 — установщик | `DisagreementProtocol-<версия>-win-x64.exe` |
| Windows x64 — без установки | `DisagreementProtocol-<версия>-win-x64-Portable.exe` |
| macOS — Apple Silicon | `DisagreementProtocol-<версия>-mac-arm64.dmg` |
| macOS — Intel | `DisagreementProtocol-<версия>-mac-x64.dmg` |

Сборки создаются вручную: **[Actions → Build installers (manual)](https://github.com/strigov/disagreement-protocol/actions/workflows/desktop.yml) → Run workflow**. Выберите платформу; после успешной сборки скачайте архив из **Artifacts**. Артефакты хранятся 7 дней, workflow не публикует GitHub Release. Для запуска workflow и скачивания нужен доступ к репозиторию.

На macOS откройте DMG и перенесите приложение в **Applications**. На Windows запустите установщик или Portable-файл.

> **Предварительные сборки.** Установщики пока не имеют подписи издателя; система может предупреждать или блокировать запуск. В документации подтверждена локальная сборка для Mac с Apple Silicon; Windows и Mac Intel требуют проверки на соответствующих системах.

Подробнее: **[сборка, установка и проверка настольного приложения](desktop/README.md)**.

## Ваши документы и данные

Разбор договора, хранение и экспорт выполняются локально. База SQLite и загруженные файлы находятся в папке данных приложения; открыть её можно через **Файл → Открыть папку данных**.

| Система | Папка данных настольного приложения |
| :--- | :--- |
| macOS | `~/Library/Application Support/DisagreementProtocol/data` |
| Windows | `%APPDATA%\DisagreementProtocol\data` |

Для полной резервной копии закройте приложение и сохраните весь каталог `DisagreementProtocol`: личные отметки проверки хранятся в профиле Electron рядом с папкой `data`. Запуск Electron из исходников использует тот же профиль приложения. Для отдельного тестового профиля задайте `DISPROT_USER_DATA`.

## Поддерживаемые документы

- **Вход:** `.docx` без макросов, до **25 MiB**. Старый формат `.doc` не поддерживается.
- **Правки:** текстовые вставки и удаления, перемещения, вставки и удаления строк и ячеек таблиц.
- **Сложные конструкции:** вложенные таблицы и правки объединения ячеек требуют предварительной обработки в Word; приложение показывает предупреждение.
- **Проверка полноты:** сопоставляет исходные правки со строками протокола. Юридическую корректность итоговых редакций проверяет пользователь.

Подробности нумерации, диагностики и ограничений — в [руководстве](docs/guide.md#границы-обработки). Примеры для проверки — в [samples](samples/README.md).

## Быстрый старт из исходников

Нужны **Windows x64 или macOS**, **uv**, **Node.js 22.19+** и **npm**. Python 3.12 устанавливается через uv. Сборка выполняется на той ОС и архитектуре, где будет работать приложение.

```bash
git clone https://github.com/strigov/disagreement-protocol.git
cd disagreement-protocol
npm ci --prefix frontend
npm ci --prefix desktop
uv sync --project backend --frozen --python 3.12 --extra dev --extra desktop
npm --prefix desktop run prepare:app
npm --prefix desktop start
```

Откроется окно **«Протокол разногласий»**. Встроенный движок запускается и завершается вместе с приложением. После изменения интерфейса или движка повторите `prepare:app` перед запуском.

Чтобы получить установщик, выполните `npm --prefix desktop run dist`. Результат появится в `desktop/dist/`. Подробнее — в [руководстве настольной сборки](desktop/README.md#локальная-сборка).

<details>
<summary><strong>Архитектура и оформление</strong></summary>

В настольной версии Electron обслуживает статический React-интерфейс на `disprot://app` и передаёт API-запросы встроенному Python-движку на случайном локальном порту. Движок завершается при закрытии приложения. Токен доступа добавляет главный процесс Electron; renderer его не получает.

Разбор выполняется фоновой задачей в процессе встроенного движка. Docker, PostgreSQL, Redis и S3 не требуются.

Цвета и размеры интерфейса задаются семантическими токенами в [`globals.css`](frontend/styles/globals.css) и [`tailwind.config.ts`](frontend/tailwind.config.ts). Общие элементы находятся в [`components/ui/`](frontend/components/ui/). Локальные шрифты Cormorant Garamond, Inter Tight и JetBrains Mono поставляются под [SIL Open Font License 1.1](frontend/public/fonts/OFL.txt).

</details>
