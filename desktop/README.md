# Настольное приложение

Electron открывает существующий React-интерфейс, собранный Vite. Python-движок упакован PyInstaller и входит в установщик; пользователю не нужны Python, Node.js или сервер. Обработка договора и экспорт работают локально.

## Установка

- Windows x64: установщик `DisagreementProtocol-<версия>-win-x64.exe`.
- Mac с Apple Silicon: `DisagreementProtocol-<версия>-mac-arm64.dmg`.
- Mac с Intel: `DisagreementProtocol-<версия>-mac-x64.dmg`.

На Mac откройте DMG и перенесите приложение в Applications. Это пока предварительные сборки без подписи издателя: Windows и macOS могут предупреждать о неизвестном разработчике или блокировать запуск. Для публичного выпуска нужны отдельная настройка подписи Windows и подпись Developer ID с notarization Apple. Текущий workflow создаёт неподписанные установщики и ничего не публикует.

Mac-пакет получает техническую ad-hoc подпись (`identity: "-"`), необходимую для корректного локального запуска. Она не удостоверяет издателя. При настройке Developer ID нужно заменить `mac.identity`, подписать Python-движок через `DISPROT_SIGN_IDENTITY` и повторно проверить entitlements и notarization; текущая конфигурация предназначена для предварительных сборок.

Первая локальная сборка проверена на Mac arm64. Windows и Mac Intel требуют проверки установщика на соответствующей системе. Репозиторий закрытый: для свободного скачивания пользователями впоследствии понадобится доступное им место публикации установщиков.

## Данные

Меню **Файл → Открыть папку данных** показывает базу и загруженные документы:

- macOS: `~/Library/Application Support/DisagreementProtocol/data`.
- Windows: `%APPDATA%/DisagreementProtocol/data`.

Закройте приложение перед резервным копированием всей папки. Обновление приложения сохраняет её; Windows-деинсталлятор её не удаляет. База разработчика `backend/data` автоматически не переносится. На стартовом экране можно продолжить работу с последним договором. Личные отметки проверки хранятся в профиле Electron рядом с папкой данных; для полной резервной копии сохраните весь каталог `DisagreementProtocol`.

## Локальная сборка

Нужны Node.js 22.19+, npm и uv. Каждая сборка выполняется на целевой ОС и архитектуре: Windows x64, macOS arm64 или macOS x64. Python 3.12 устанавливается через uv.

Из корня репозитория:

```sh
npm ci --prefix frontend
npm ci --prefix desktop
cd backend
uv sync --frozen --python 3.12 --extra dev --extra desktop
cd ../desktop
npm run dist
```

Результат лежит в `desktop/dist`. В установщик попадают только код, статический интерфейс и Python-движок; тестовые договоры и пользовательская база не включаются.

`npm run prepare:app` отдельно собирает интерфейс и движок; после него `npm start` запускает приложение для разработки. `npm run pack` создаёт каталог приложения без установщика. Для отдельного тестового профиля задайте `DISPROT_USER_DATA` перед запуском.

## Проверка

```sh
# Из desktop
npm test
# Из backend, после prepare:app; на Windows добавьте .exe к имени executable
uv run --frozen python ../desktop/scripts/smoke-engine.py ../desktop/build/backend/disprot-engine/disprot-engine
```

Smoke-тест запускает готовый executable во временной папке с кириллицей и пробелами, загружает синтетический договор, строит протокол, редактирует строку, проверяет DOCX и сохранение правок после перезапуска. Он также проверяет отклонение запросов без токена и завершение движка при закрытии stdin родителя. Для локальной проверки своего договора предусмотрен `--contract /путь/к/договору.docx`.

Перед распространением проверьте установку, загрузку договора через интерфейс, правку, системный диалог сохранения, повторное открытие и удаление приложения на каждой ОС.

## Ручная сборка GitHub Actions

**Actions → Build installers (manual) → Run workflow**. Выберите одну платформу или `all`. Архив установщика появится в Artifacts и хранится 7 дней. Push, pull request и теги ничего не запускают. Запуск расходует минуты GitHub Actions; `all` использует три runner. Workflow не создаёт GitHub Release.

## Связь интерфейса с движком

Интерфейс работает на постоянном адресе `disprot://app`; маршруты и localStorage сохраняют один origin между запусками. Electron обслуживает статические файлы и пересылает `/api` в Python на случайном порту `127.0.0.1`. Токен генерируется заново при запуске и добавляется главным процессом; renderer его не получает. Node.js в renderer выключен, sandbox включён, внешняя навигация и сетевые запросы renderer запрещены. При закрытии приложения завершается дочерний движок.
